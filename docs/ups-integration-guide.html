UPS 整合完整工程文件

本文件完整描述 PAXIS 系統中 UPS 出貨整合的設計與實作細節，包含認證流程、多租戶憑證解析、費率查詢、建立提單、預約提貨，以及平台加成機制。供 Patisco 前後端工程師 follow 並移植到正式環境。

參考系統： PAXIS（paxis.tw） 技術棧： Next.js 14 · TypeScript · Prisma · PostgreSQL UPS API 版本： Rating v2403 · Shipments v2403 · Pickup v2201 文件日期： 2026-07-13

01 架構概覽

PAXIS 的 UPS 整合採用平台帳號代管 + 租戶自有帳號並存的雙軌設計。所有 UPS API 呼叫使用同一組 OAuth 2.0 client credentials（環境變數 `UPS_CLIENT_ID` / `UPS_CLIENT_SECRET`），但帳單帳號（Account Number）因租戶設定而異。

02 環境變數

以下環境變數需設定於部署環境（Vercel / 伺服器），不進版本控制：

變數名稱必填說明
UPS_CLIENT_ID 必填 UPS Developer Account 的 OAuth Client ID。在 UPS Developer Portal 建立應用時取得。
UPS_CLIENT_SECRET 必填 對應的 Client Secret。
XINOSYS_UPS_ACCOUNT_NO 選填 平台（錫諾系統）自有 UPS 帳號的 fallback 環境變數。通常從 DB 讀取（ADMIN_Setting.ups_xinosys_account_no），若 DB 為空才讀此環境變數。
UPS_DISCOUNT_MULTIPLIER 選填 加成乘數的 env fallback，通常從 DB 讀取。
UPS Developer Portal

前往 developer.ups.com → 建立應用 → 選擇「I need API access to UPS technology」→ 取得 Client ID 和 Client Secret。OAuth 2.0 client_credentials grant 不需要用戶授權，適合伺服器端使用。

05 UPS OAuth 認證

UPS API 使用 OAuth 2.0 client_credentials grant。每次呼叫 UPS API 前需先取得 Bearer token，有效期 4 小時。

Token 端點
POST https://onlinetools.ups.com/security/v1/oauth/token
Request
// Headers
Authorization: Basic BASE64(CLIENT_ID:CLIENT_SECRET)
Content-Type:  application/x-www-form-urlencoded

// Body
grant_type=client_credentials
Response
{
  "access_token": "eyJhbGci...",
  "expires_in":   "14399"   // 秒數（字串）≈ 4 小時
}
Token 快取策略（PAXIS 實作）

在 module level 快取 token，同一 serverless instance 共用。設定 5 分鐘提前更新緩衝，避免在快到期時被使用到剛失效的 token：

// src/lib/shipping/ups-auth.ts

let _cache: { accessToken: string; expiresAt: number } | null = null

export async function getUpsAccessToken(): Promise<string> {
  // 距過期超過 5 分鐘才算有效
  if (_cache && _cache.expiresAt - Date.now() > 5 * 60 * 1000) {
    return _cache.accessToken
  }

  const credentials = Buffer.from(`${clientId}:${clientSecret}`).toString('base64')
  const res = await fetch(UPS_TOKEN_URL, {
    method: 'POST',
    headers: {
      Authorization: `Basic ${credentials}`,
      'Content-Type': 'application/x-www-form-urlencoded',
    },
    body: 'grant_type=client_credentials',
  })

  const data = await res.json()
  _cache = {
    accessToken: data.access_token,
    expiresAt: Date.now() + parseInt(data.expires_in, 10) * 1000,
  }
  return _cache.accessToken
}
Serverless 注意事項

Vercel serverless function 每次冷啟動都會重置 module-level 變數，_cache 會清空。這是預期行為：冷啟動後會重新取 token，warm instance 之間才能共用快取。不需要額外處理。

06 憑證解析邏輯

resolveUpsCreds(tenantPrisma) 是所有 UPS 功能的入口，決定這次請求要用哪個帳號出帳、是否有加成乘數。

解析優先順序（Waterfall）
if (租戶 DB 有 ups_own_account_no 或 ups_xinosys_account_no) → return { accountNo: 租戶帳號, source: 'own', discountMultiplier: 租戶乘數 } else if (租戶 DB ups_mode === 'managed') → 從主 DB（ADMIN_Setting）讀取平台帳號和全局乘數 → return { accountNo: 平台帳號, source: 'managed', discountMultiplier: 全局乘數 } else → return null // UPS 服務未開通
完整實作（src/lib/ups.ts）
export interface UpsCreds {
  accountNo:          string
  discountMultiplier: number | null
  source:             'own' | 'managed'
}

export async function resolveUpsCreds(tenantPrisma: PrismaClient): Promise<UpsCreds | null> {
  // 1. 查租戶自有帳號（含舊版 key 向後相容）
  const [ownAccountRow, legacyAccountRow] = await Promise.all([
    tenantPrisma.sYS_KeyValue.findUnique({ where: { key: 'ups_own_account_no' } }),
    tenantPrisma.sYS_KeyValue.findUnique({ where: { key: 'ups_xinosys_account_no' } }),
  ])
  const ownAccount = ownAccountRow?.value?.trim() || legacyAccountRow?.value?.trim()

  if (ownAccount) {
    // 有自有帳號：讀取此租戶的議價乘數（非強制）
    const multiplierRow = await tenantPrisma.sYS_KeyValue
      .findUnique({ where: { key: 'ups_own_discount_multiplier' } })
    const multiplier = multiplierRow?.value ? parseFloat(multiplierRow.value) : null
    return { accountNo: ownAccount, discountMultiplier: multiplier, source: 'own' }
  }

  // 2. 查是否為代管模式
  const modeRow = await tenantPrisma.sYS_KeyValue
    .findUnique({ where: { key: 'ups_mode' } })
  if (modeRow?.value === 'managed') {
    // 從主 DB（ADMIN_Setting）讀取平台帳號
    const platformAccount = await getSystemSetting('ups_xinosys_account_no')
    const accountNo = platformAccount?.trim() || process.env.XINOSYS_UPS_ACCOUNT_NO
    if (!accountNo) return null
    const multiplierStr = await getSystemSetting('ups_discount_multiplier')
    return {
      accountNo,
      discountMultiplier: multiplierStr ? parseFloat(multiplierStr) : null,
      source: 'managed',
    }
  }

  return null  // 未開通
}

07 三種運作模式

模式條件帳單帳號費率顯示誰出帳
disabled no ups_mode，no ups_own_account_no 無 功能鎖定，顯示「請聯繫開通」 無
managed ups_mode = 'managed' 平台帳號（ADMIN_Setting） UPS 報價 × 乘數（基本運費部分） 錫諾系統向租戶收費
own 有 ups_own_account_no 租戶自有帳號（覆蓋代管） 直接顯示 UPS 議價費率 UPS 直接向租戶收費

優先順序：own > managed > disabled。同一租戶若同時設定了 ups_own_account_no 和 ups_mode = 'managed'，自有帳號優先。清空 ups_own_account_no 後，才會 fallback 到代管。

08 加成機制（Markup）

加成公式

代管模式下，平台對基本運費（Base Charge）套用乘數，附加費（燃油費、偏遠費等）不加成，因為這些費用屬公開揭露收費，租戶可自行查核。

收費金額 = (Base Charge × 乘數) + Σ 附加費 + 稅費 例：Base = $100，乘數 = 1.2，燃油費 = $15 → 收費 = (100 × 1.2) + 15 = $135
API 端的加成計算（src/app/api/shipping/rates/route.ts）
const result = options.map(opt => {
  if (source === 'managed' && discountMultiplier != null
      && opt.chargeBreakdown?.baseCharge != null) {
    const { baseCharge, surcharges, taxAmount } = opt.chargeBreakdown
    const surchargesTotal = surcharges.reduce((s, c) => s + c.amount, 0)
    const markedUpAmount = parseFloat(
      (baseCharge * discountMultiplier + surchargesTotal + (taxAmount ?? 0)).toFixed(2)
    )
    return { ...opt, amount: markedUpAmount, contractEstimate: null }
  }
  // 自有帳號：原樣輸出，contractEstimate 供參考
  return {
    ...opt,
    contractEstimate: discountMultiplier != null
      ? parseFloat((opt.amount * discountMultiplier).toFixed(2))
      : null,
  }
})

包裹數量處理邏輯

UPS Rating API 每次最多 50 個包裹。PAXIS 的處理方式：

  • quantity 大於 1 的包裹，先展開成多個單件

由錫諾系統人員操作，用於設定代管帳號和全局加成乘數。

路由

POST Request Body

帳號來源顯示邏輯

GET 回傳的 source 欄位有三種值：

  • 'db' — 帳號來自 DB（正常情況）
  • 'env' — DB 無值，fallback 到環境變數 XINOSYS_UPS_ACCOUNT_NO
  • 'none' — 尚未設定
乘數驗證規則

乘數必須大於 0。後端已驗證 n <= 0 會回傳 400。前端 UI 顯示計算說明：1.2 = 基本運費加收 20%，0.9 = 基本運費打 90% 折（議價反向）。

  • 代管啟用中（blue）— upsMode === 'managed'：「✓ 目前使用平台代管 UPS 服務」
  • 未開通（yellow warning）— 兩者都沒有：「⚠ 請聯繫錫諾系統開通或填入自有帳號」

租戶只能設定自己的帳號（ownAccountNo），無法更改代管模式。代管模式由平台後台控制（寫入租戶 DB 的 ups_mode）。

14 Patisco 實作步驟

以下步驟假設 Patisco 是多租戶架構（每個租戶有獨立 DB），與 PAXIS 的多租戶模型相同。請依 Patisco 實際的設定儲存機制調整。

Step 1 — 建立 UPS Developer 應用
  1. 至 developer.ups.com 建立帳號並新增 App
  2. 選擇需要的 API：Rating API、Shipping API、Pickup API
  3. 取得 Client ID 和 Client Secret，設定為環境變數 UPS_CLIENT_ID / UPS_CLIENT_SECRET
Step 2 — 建立資料庫 Schema
  1. 在每個租戶的 DB 建立 SYS_KeyValue 表（見 §03）
  2. 在主 DB（ADMIN_Setting）新增 UPS 相關欄位
  3. 建立 UPS_ShipmentLog 表（見 §03）
Step 3 — 移植核心 Library

以下四支檔案可直接移植，幾乎不需修改：

Step 4 — 實作憑證解析

根據 §06 的 resolveUpsCreds() 邏輯，依 Patisco 的 DB 架構實作：

// 偽代碼，依 Patisco DB 客製化
async function resolveUpsCreds(tenantId: string) {
  // 1. 查此租戶的自有帳號
  const ownAccount = await getTenantSetting(tenantId, 'ups_own_account_no')
  if (ownAccount) {
    const multiplier = await getTenantSetting(tenantId, 'ups_own_discount_multiplier')
    return { accountNo: ownAccount, discountMultiplier: multiplier, source: 'own' }
  }
  // 2. 查代管模式
  const mode = await getTenantSetting(tenantId, 'ups_mode')
  if (mode === 'managed') {
    const platformAccount = await getPlatformSetting('ups_account_no')
    const multiplier = await getPlatformSetting('ups_multiplier')
    if (!platformAccount) return null
    return { accountNo: platformAccount, discountMultiplier: multiplier, source: 'managed' }
  }
  return null
}
Step 5 — 建立 API Route

參考 §09–§11 實作三個 API endpoint：

  • 費率查詢：呼叫 resolveUpsCreds() → getUpsAccessToken() → getUpsRates() → 套用加成公式
  • 建立提單：呼叫 createUpsShipment() → 寫 UPS_ShipmentLog
  • 預約提貨：呼叫 scheduleUpsPickup() → 更新 UPS_ShipmentLog.pickupConfirmationNo
Step 6 — 建立設定 UI
  • 平台後台：設定代管帳號（ups_account_no）和加成乘數（ups_multiplier）
  • 平台後台 → 租戶管理：開啟/關閉各租戶的代管模式（寫入租戶 DB 的 ups_mode）
  • 租戶設定：允許租戶填入自有帳號（ups_own_account_no）
